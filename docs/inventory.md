# 在庫管理

販売商品・消耗品の数量と入出庫を、同じ端末・ブラウザー内で記録する無料ツールです。広告や会員登録はありません。
ホームの「在庫を管理する」から開きます。下部の共通メニューは従来の5項目を維持します。

## 基本の使い方

1. 商品名、単位、数量などを入力して商品を登録します。必要に応じて品番、バーコード、補充基準、参考価格を入力します。
2. 商品を選び、入庫または出庫の数量を入力します。保存する前に商品・数量・方向を確認してください。
3. 商品検索や入出庫履歴から、現在の数量と過去の動きを確認します。
4. 設定・バックアップからJSONを保存します。機種変更やブラウザーのデータ削除前にも行ってください。

バーコードは同じアプリに登録した商品を探すための情報です。外部の商品データベースへの問い合わせ、商品名・価格の自動取得は行いません。
先頭のゼロを含むコードも文字として扱います。商品名などが不明な場合は実物を確認して手入力してください。

## 写真とバーコード

「写真からバーコードを読み取る」→「写真を撮る・画像を選ぶ」のファイル選択を押してください。
端末の標準画面から写真撮影・フォトライブラリ・ファイル選択を利用します。選択肢はOS・ブラウザーによって異なります。
`accept="image/*"` を使い、撮影だけに限定する `capture` は指定しません。アプリ内のリアルタイムカメラ表示や連続スキャンはありません。

選択後は「写真を解析しています…」を表示します。コード全体を明るく鮮明に写してください。
読み取れなければ写真を撮り直すか、バーコード番号を手入力して検索できます。同じ写真の再選択も可能です。
登録済みなら商品詳細、未登録ならバーコードを入力済みの商品登録画面へ進みます。読み取りだけでは在庫や履歴は変わりません。

対応形式はEAN-13、EAN-8、UPC-A、UPC-E、Code 128、QRコードです。QRコード内のURLを自動で開くことはありません。
同梱ZXingと既存の回転対応を使用します。画像は30MiB・2,500万画素・各辺12,000px以下が対象で、SVGは使えません。
HEIC等を実際に開けるかはブラウザーに依存します。開けない画像はPNG/JPEGへの変換を案内します。
解析は端末内で行い、画像や番号を外部送信しません。実行時の外部CDNも不要です。ライセンスは `inventory/vendor/` に同梱しています。

## 数量・履歴・参考価格

入出庫履歴の数量と単位は記録時点の内容として扱い、履歴がある商品の単位は変更できません。
別の単位で管理する場合は別の商品として登録してください。過去の数量を別の単位へ自動換算しません。

価格は**税込の参考値**です。税率は未確定として扱い、消費税・仕入税額・原価や利益の税務計算は行いません。
参考価格を、領収書・見積書・会計帳簿へ自動転記する機能はありません。

## 端末内保存とバックアップ

在庫データはブラウザーのIndexedDBに保存します。個人情報・商品情報・履歴を外部のデータベースに送信しません。
ただし、アプリのHTML・JavaScript等の取得には通常の通信が発生します。保存先はURLのドメイン、端末、ブラウザーごとに分かれます。
GitHub Pages版とCloudflare Pages版は同じデータを共有しません。

統合バックアップのバージョン4には在庫が含まれます。復元前に現在のバックアップを保存してください。
旧バージョン1〜3のバックアップを復元したときは、そのファイルに在庫が含まれないため現在の在庫を保持します。

統合バックアップはlocalStorageと複数のIndexedDBを扱います。復元全体を一度に確定するトランザクションではありません。
容量不足・タブの終了・ブラウザーのエラー等で一部だけ復元された場合は、エラー内容を確認し、保存しておいたバックアップから再実行してください。
端末の空き容量、ブラウザーの保存設定、シークレットモード、サイトデータ削除により、保存できない・消える場合があります。
データ保存の代わりとしてオフラインキャッシュを扱わないでください。キャッシュに利用者の在庫データやバックアップファイルは保存しません。

## オフライン

一度オンラインで読み込み、サービスワーカーの準備が完了すると、同梱済み画面や読取ライブラリをオフラインで利用できます。
初回アクセス、キャッシュ未作成、ブラウザーによるキャッシュ削除の直後は、オンラインで読み込んでください。
撮影・写真選択の挙動は端末側の機能に依存します。

## 確認状況と試験方法

以下は自動試験の対象です。画像読み取りには自作の合成画像を使用し、実機試験とは区別します。

| 検証 | 結果 |
| --- | --- |
| 登録・編集・アーカイブ、分類、商品名/品番/バーコード検索 | 成功 |
| 先頭0・バーコード重複防止・品番重複警告 | 成功 |
| 入庫・出庫・棚卸、マイナス防止、小数数量、履歴・単位固定 | 成功 |
| 同時更新・保存中の画面移動・保存失敗の原子的な取消 | 成功 |
| ブラウザー再起動後の保持・HTML文字列の安全な表示 | 成功 |
| JAN-13/8・UPC-A/E・Code 128・QR画像読取 | 成功 |
| 写真選択・解析中表示・再試行・閉じた後の結果破棄・手入力 | 自動試験対象 |
| v4全データ復元、v1〜3読込時の在庫保持、不正/中断時の保護 | 成功 |
| ルートと `/shop-tools/`、オフライン操作、SW更新・旧キャッシュ削除 | 成功 |
| 領収書/見積PDF・写真報告・手取り/口コミ/キャンセル・旧星評価データ保持 | 成功 |
| 別originバックアップ復元・静的GET以外の送信なし | 成功 |

**iPhone Safari・Android実機での写真撮影・写真選択・ホーム画面追加・オフライン動作は未検証**です。
自動試験での合成画像の解析だけでは、実際のピント、反射、曲面、撮影条件を保証できません。
UPC-Eは同梱ライブラリに対する互換処理を含みます。[ライブラリ・ライセンス・合成画像の詳細](barcode-library.md)を参照してください。

公開用ファイルの生成とパスの確認:

```text
node scripts/build-cloudflare.mjs
node --test tests/cloudflare-build.test.mjs
```

生成した `dist/` をローカルWebサーバーで配信し、Playwrightを用意した環境で次を実行します。
標準URLは `http://127.0.0.1:8765` です。別URLは環境変数 `TEST_BASE_URL` で指定します。

```text
node tests/inventory.cjs
node tests/inventory-safety.cjs
node tests/inventory-backup.cjs
node tests/barcode-decode.cjs
node tests/inventory-photo.cjs
node tests/inventory-offline.cjs
```

CIではルート `/` とGitHub Pages相当の `/shop-tools/` の両方で実行します。
既存の領収書・見積書・計算機・写真報告・バックアップ移行試験も併せて確認します。

`inventory-offline.cjs` は独立したlocalhostサーバーを起動し、両方のパスを検証します。`TEST_WEB_ROOT=dist` で生成物を対象にできます。localhostではテスト内でSWを登録し、通常の待機→全タブ終了→有効化の更新動作を確認します。アプリの公開環境での自動登録は従来どおりHTTPS限定です。

## 本番を変更せずiPhoneで確認する手順

このPRは公開設定を変更せず、自動マージしません。作業ブランチは `feature/inventory-barcode`、基点とPRの宛先は未マージのPR #9に対応する `cloudflare/pages-preparation` です。この宛先へのマージは現在のCloudflare本番の自動更新を起こすため、比較確認が済むまでマージしないでください。

1. iPhone Safariで検証専用URL https://shop-tools-inventory-test.pages.dev/inventory/ を開きます。本番とは別プロジェクトで、`feature/inventory-barcode` の変更が自動反映されます。
2. 「写真からバーコードを読み取る」→ファイル選択を押し、OSの撮影と保存済み写真選択の両方を確認します。未登録コードなら商品登録画面へ進みます。
3. 架空の商品を登録し、同じ写真をもう一度読み取って商品詳細が開くことを確認します。縦向き・横向きの写真でも試してください。
4. 白紙などで読み取り失敗と撮り直し案内を確認し、手入力でも検索します。読取だけで数量や履歴が変わらないことを確認します。
5. 入庫2・出庫1を確定し、履歴、Safari再起動後の保持、オンライン準備後の機内モードでの入出庫・保存画像読取、v4バックアップの書出し・復元を確認します。

テストURLと本番URLの保存データは別です。プライベートブラウズを避け、実際の業務データを入れる前に架空の商品で確認してください。
PR #9・#10はマージせず、既存Cloudflareプロジェクト `shop-tools` とGitHub Pagesを変更しません。
